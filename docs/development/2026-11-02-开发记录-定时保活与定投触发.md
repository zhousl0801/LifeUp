# 2026-11-02 外部定时保活与定投触发

## 背景

服务部署在 Render 免费实例上，数据库在 Supabase。Render 免费 web service 空闲 15 分钟会休眠，休眠时进程停止，`PlanSchedulerService` 与 `QuoteRefreshSchedulerService` 两个后台服务随之停止，定投计划到期不会执行，行情也不会刷新。

因此需要外部定时任务在服务休眠时唤醒它，并显式触发到期计划执行。

## 结论

服务端新增一个机器调用入口，GitHub Actions 负责按时唤醒并触发。登录 Cookie 体系不变，机器入口改用共享令牌。

## 服务端改动

- 新增 `api/src/LifeUp.Api/Controllers/CronController.cs`：
  - `POST /api/cron/plans/run`，`[AllowAnonymous]`，不走登录 Cookie。
  - 令牌从配置键 `Cron:Token`（环境变量 `Cron__Token`）读取，请求头 `X-Cron-Token` 携带。
  - 未配置令牌：返回 503，入口关闭，不泄露任何细节。
  - 令牌不匹配或缺失：返回 401。
  - 比较使用 `CryptographicOperations.FixedTimeEquals`，避免逐字节试探。
  - 令牌只从配置读取，不写日志、不回显。
- 令牌只授予「执行到期计划」这一个动作，等于开放登录后的写能力，因此必须足够长（建议 `openssl rand -hex 32`），并且只放在 Render 环境变量与 GitHub Secrets 里。
- 接口幂等：`PlanExecutionService.RunDueAsync` 按期次去重，重复调用不会重复扣款，晚跑会把当天该跑的补齐。

## 工作流

### `.github/workflows/daily-plan-run.yml`

- 触发：`cron: '30 4 * * *'`（04:30 UTC = 北京时间 12:30），另支持手动 `workflow_dispatch`。
- 步骤：检查密钥 → 每 10 秒探活 `/api/health`，最多 5 分钟（覆盖 Render 免费实例约 1 分钟的冷启动）→ 带令牌 `POST /api/cron/plans/run`，失败重试 3 次。
- 为什么必须先探活：休眠实例收到请求后要 30–60 秒才起得来，直接 POST 会在冷启动期间失败。

### `.github/workflows/keep-warm.yml`

- 每 10 分钟打一次 `/api/health`，让实例保持唤醒，消除打开 APP 时的冷启动等待。
- **默认关闭**：由仓库变量 `KEEP_WARM_ENABLED == 'true'` 控制。
- 原因：私有仓库每月 2000 Actions 分钟，每 10 分钟一次约 4300 分钟/月，会超额。公开仓库 Actions 不计量；私有仓库建议改用 cron-job.org / UptimeRobot 这类免费定时服务打同一个 URL。
- 冷启动时请求可能超时，但请求已到达 Render，足以阻止休眠，因此该步骤不判定失败。

## 配置步骤

1. Render 服务环境变量新增 `Cron__Token`（`openssl rand -hex 32` 生成），`render.yaml` 中已加 `sync: false` 占位。
2. GitHub 仓库 Settings → Secrets and variables → Actions 新增：
   - `APP_BASE_URL`：服务根地址，例如 `https://your-service.onrender.com`（不带结尾斜杠）。
   - `CRON_TOKEN`：与 `Cron__Token` 完全一致。
3. 需要保活时再新增仓库变量 `KEEP_WARM_ENABLED = true`。

## 验证

- 新增 `api/tests/LifeUp.Tests/Api/CronEndpointsTests.cs` 五个用例：未配置令牌 503、缺令牌头 401、错误令牌 401、正确令牌 200 且无需登录、健康检查仍匿名。
- 后端 354 项：336 通过、18 项真实 PostgreSQL 用例跳过。
- 端到端（本机 5071，Development，连真实库）：
  - 无令牌 `POST /api/cron/plans/run` → 401
  - 错令牌 → 401 `定时调用令牌无效。`
  - 正确令牌 → 200 `{"createdOccurrences":0,"completed":0,"waiting":0,"failed":0}`（今日 12:30 的期次已由本地常驻调度完成，故本次无可执行期次）
  - 未登录访问 `/api/ledger` → 401，登录体系未受影响
- 顺手修复一个跨月失效的测试：`LedgerEndpointsTests.GetMonthChange_WithoutCompleteAssets_ReturnsEmptyChangeAndNotes` 原来依赖「今天仍在账本起始日的同一个月」，进入 11 月后断言失败；改为固定时钟到 2026-10-20。

## 需要注意

- GitHub 的定时任务在仓库连续 60 天无提交后会自动停用，届时需要手动重新启用。
- GitHub Actions 的 schedule 不保证准点，高峰期可能延迟十几分钟。定投日期精度不受影响（幂等补齐），但不要用它做秒级任务。
- 保活只是阻止休眠，不等于免费额度无限：Render 免费 web service 每月 750 实例小时，全天候唤醒约 730 小时，刚好在额度内，没有余量。
- 本地常驻进程在 2026-11-02 12:30 正常执行了四笔基金定投（200 + 100 + 640 + 100 = 1,040 元），说明逻辑本身没问题，缺的只是生产环境被唤醒。
