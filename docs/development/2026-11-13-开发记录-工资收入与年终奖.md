# 2026-11-13 开发记录 · 工资收入与年终奖

关联：[设计规格](../design/工资收入与年终奖-设计规格-2026-11-13.md)、[实现计划](../../.handoff/plans/2026-11-13-工资收入与年终奖-实现计划.md)、[资本积累与目标](2026-11-13-开发记录-资本积累与目标.md)

## 1. 目标

把工资、公积金和年终奖从三个地方手工维护，收敛到一个工资档案：

- 档案保存时同步工资、公积金缴存和年终奖三个自动计划，改薪只改一处。
- 资本积累预测默认读取档案的税后工资、公积金和年终奖，年终奖按发放月计入。
- 月均积累仍表示每月实际值（含公积金），年终奖单独展示，不摊平。
- 没有工资档案时，现有自动计划、资本假设和预测行为不变。

## 2. 实际变更

### 2.1 工资档案与计划同步

- 新增 `SalaryProfile` 领域记录和校验；工资档案以 JSONB 存在 `ledgers.salary_profile`。
- 新增 `SalaryProfileService`，在账本锁和一次保存内同步：
  - 工资到账（每月，税后工资）；
  - 公积金缴存（每月，个人＋单位合计）；
  - 年终奖到账（每年，发放月 + 发薪日）。
- 新建计划从严格晚于今天的下一个发薪日 / 发放日开始，不补记已经过去的日期。
- 管理中的工资、公积金、年终奖计划金额只读；年终奖计划只保留暂停 / 恢复；管理中的计划隐藏删除。
- 「我的 → 个人信息」新增「工资档案」入口（与「头像与昵称」相同的 list-row），放在「头像与昵称」之后；点击进入 `/salary` 详情页；自动计划页只保留管理计划的标记和只读提示。
- 分栏标题之间统一 `--space-6` 上间距，个人信息 / 个性化设置 / 数据管理的间隔一致。
- 详情页默认脱敏（`••••`），头部提供「显示金额 / 隐藏金额」和「编辑」；提供「自动计划」入口。
- 卡片只展示税后与积累口径：税后工资、公积金、年终奖到手额度（与第二列左对齐）、年度到手现金、公积金年积累；不再展示年终奖月数 / 到账月份、税前 Base、税前年终奖和税前年包。
- 自动计划的年终奖卡片与工资卡片统一：工资档案标记放在计划名称旁且不换行；移除年终奖卡片的「由工资档案管理；暂停后不再自动记账」说明。
- 年终奖文案改为「每年 M 月到账」，不再写「次年」。
- 工资档案弹层使用主按钮样式，输入框统一 `box-sizing` 和两列最小宽度，修复横向滚动；Playwright 在 390 / 430 宽度验证 `scrollWidth = clientWidth`。
- 停用工资档案后计划保留，金额恢复可编辑；资本目标补上空的工资、公积金和年终奖字段，避免预测跳变。

### 2.2 年终奖计划

- 新增 `AutoPlanType.BonusIncome` 和 `AutoPlanCycle.Yearly`；计划增加可空 `month_of_year`。
- 年度期次键为 `Y{yyyy}`，同年只生成一次；短月按月末，1 月发放落在下一个 1 月。
- 年终奖入账使用「奖金」分类（系统标识 `bonus`），分类缺失或停用时回落到「工资」。
- 执行顺序调整为工资 → 年终奖 → 缴存 → 提取 → 定投。

### 2.3 资本预测与目标页

- `CapitalGoal` 增加年终奖到手、发放月和「跟随工资档案」开关；资本目标仍是 JSONB。
- 解析器优先级：档案（跟随开启）> 目标手填值 > 最近 6 个完整月均值 > 默认值。
- 计算器在发放月计入年终奖，并随收入年增长放大；`monthlyNetAccumulation` 保持月度口径，年度表净储蓄含年终奖。
- 本月实际的预期净积累在发放月加上年终奖，并给出到账时间说明。
- 目标页 Hero 不再显示公积金 / 年终奖说明；顶部功能栏在「调整假设」左侧增加全局金额显示 / 隐藏眼睛，和首页共用 `amountsMasked`。
- 假设弹层可切换跟随 / 手动，手动切换时用生效值预填。
- 年度表表尾注明净储蓄含年终奖。

### 2.4 备份与迁移

- 备份版本从 4 升到 5，新增 `SalaryProfileJson` 和计划 `MonthOfYear`；4 版备份仍可恢复。
- 迁移 `AddSalaryProfile`、`AddYearlyPlanSupport`：新增两个可空列，并回填「奖金」分类的 `bonus` 系统标识。
- 已在用户授权下应用到真实账本库；应用前导出完整备份 `output/lifeup-backup-2026-11-13-before-salary.json`（本地，未入库）。

## 4. 已知边界

- 年终奖到手由用户填写，App 不做个税估算；自动入账使用档案里的预计值，实际不同时修改那一笔。
- 年终奖发放日统一使用发薪日；实际发放日不同时，生成后可在账单里修改记录日期。
- 公积金只录个人＋单位合计，不拆分个人和单位。
- 公积金和年终奖的 0↔正数切换用旧档案值判断；用户曾手动暂停又被档案归零时，恢复按档案优先。
- 工资档案保存后，旧的手填资本假设不会被清空；切换「跟随工资档案」后以档案为准。
- 浏览器写路径验收和真实账本上的工资档案录入需要用户重启本地 API 后自行完成。
