# 2026-11-04 基金卡片口径、交易排序与建账前收益入口收口

## 背景

三个问题集中在基金页：

1. 顶部总额和每只基金的金额对不上，差额正好等于待确认买入（实测 2,080.00）。
2. 交易记录把未确认的单据混在已完成的流水里按时间排，需要盯的那几笔会沉到中间。
3. 持仓展开区的信息太密，其中「建账前已实现 + 修改」占一行，实际很少用。

## 1. 基金卡片的资产口径

`FundSummaryDto` 一直同时带着两个值：

- `Value`：已确认份额的估值。
- `AssetValue`：`Value + 待确认买入（按 T 日净值折算）+ 待到账`。

顶部 `scope.assetValue` 用的是后者，基金卡片主数字用的却是 `formatMoney(fund.value)`。所以只要有一只基金买到还没确认，卡片之和就比顶部少一块——资产没算错，是两个口径混着用。

改法：卡片主数字改用 `fund.assetValue`，并在占比后面补一句「含待确认 ¥xxx」，让差额有出处。待确认部分仍不进持有收益和持有成本，口径不变。

验证（真实库）：卡片之和 276,070.19 = 顶部 276,070.19，四只带待确认的基金分别标出 1,280 / 400 / 200 / 200。

## 2. 交易记录的排序

`activityRows` 原来只有一条 `right.timestamp.localeCompare(left.timestamp)`。改成两段：

```ts
return rows.sort((left, right) => {
  if (left.isPending !== right.isPending) {
    return left.isPending ? -1 : 1
  }

  return right.timestamp.localeCompare(left.timestamp)
})
```

未确认（买入待确认、赎回申请中、待到账）置顶，各组内仍按时间倒序。已撤销的记录按已完成处理，不上浮。

## 3. 建账前已实现收益只留录入入口

原来的做法是持仓录入之后再单独补录：展开基金 → 平台行「建账前已实现 +2,762.09 修改」→ 弹层填金额。日常几乎用不到，却每次展开都占一行。

- `CreateFundPositionRequest` 早就带 `PriorRealizedProfit`，后端 `CreatePositionCoreAsync` 也一直在用，只是前端表单没给入口。补上「建账前已实现收益（元）」输入框，留空按 0，随录入一起提交。
- 删掉持仓展开区的 `prior-profit-line` 与「修改」按钮，删掉 `priorProfit` 弹层、`openPriorProfitSheet`、`submitPriorProfit` 和 `setFundPriorRealizedProfit` 的前端调用。
- 后端 `POST /api/ledger/funds/positions/{positionId}/prior-realized-profit` 保留不动：数据仍在，历史值继续计入已实现盈亏与累计收益。

## 顺带的展开区瘦身

- 单平台持仓不再重复显示份额（类别标题里已有），只在多平台合并时逐平台列出份额。
- 「同一基金的 A/C 类分别列示份额和净值」这句说明只在真的有两个类别时出现；行情依据不足的提示独立成句。
