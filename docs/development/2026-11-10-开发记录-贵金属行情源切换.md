# 2026-11-10 开发记录：贵金属行情源切换

## 1. 问题

积存金报价刷新间歇性失败，状态接口和持仓上记录的错误是 `The SSL connection could not be established, see inner exception.`。11-10 16:44 失败，16:48 再刷新又成功，返回工行积存金主动积存价 882.34 元/克。

用 curl 和独立的 .NET 探针请求同一接口都能正常返回，说明工行接口本身可用，失败发生在本机长驻 API 进程与工行站点之间的 TLS 握手环节，属于间歇故障。原来只有工行一个来源，失败一次就会把整项标成失败，因此改为多来源。

## 2. 选源

| 候选 | 当时价格（元/克） | 与积存金的关系 |
| --- | --- | --- |
| 工行积存金 | 882.34 | 银行实际平台报价 |
| 上金所 Au99.99（黄金9999） | 883.42 | 积存金的定价基准，价差约 0.1% |
| 上期所沪金 au2612 | 885.12 | 期货合约，存在基差和换月 |

沪金是期货，不能直接当作积存金价格。东方财富也只提供具体月份合约，做连续行情需要自行拼接主力合约。上金所 Au99.99 是积存金加减点差的基准，价格最接近，所以选它做默认来源，工行报价保留为备用。

## 3. 实现

- 新增 `SgeGoldQuoteProvider`，通过东方财富公开行情读取上金所 Au99.99（`secid=118.AU9999`），来源记为 `eastmoney_sge`。主站不可用时切到备用站点。
- 新增 `GoldQuoteProvider` 组合两个来源：先取上金所现货，异常时再取工行积存金；两者都失败才返回行情不可用，并保留最后一次错误信息。
- `QuoteProviderOptions` 新增 `GoldSgeBaseUrl` 和 `GoldSgeFallbackBaseUrl`，默认指向 `push2.eastmoney.com` 与 `push2delay.eastmoney.com`；`GoldBaseUrl` 继续用于工行。
- `Program.cs` 改为分别注册两个独立 HttpClient，再把组合提供方注册为 `IGoldQuoteProvider`。
- 行情记录继续保存实际来源，原有历史、估值和失败状态逻辑不变。

## 5. 边界

- 上金所现货只在交易时段更新，非交易时段返回最近收盘价和对应日期。
- 工行报价仍可能在 TLS 握手阶段失败；有现货主源时不再影响刷新结果。
- 两个来源都不可用时仍然明确报错，保留最近有效值，不生成推算价格。
- 来源顺序固定在代码里，配置只调整接口地址。
- 未做浏览器页面验收，页面展示沿用现有报价和来源字段。
