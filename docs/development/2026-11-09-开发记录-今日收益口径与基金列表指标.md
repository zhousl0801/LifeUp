# 2026-11-09 基金页今日收益口径与列表指标

## 问题

基金页「今日收益」显示 **-16,974.75**，收益页 11-05 的当日合计是 **-19,167.40**，11-06 是 **+401.18**（仅银华披露）。同一个账本出现三个数。

原因有三处：

1. 基金页把每只基金各自最新净值日的收益直接相加。7 只基金停在 11-05，银华已经到 11-06，两天的涨跌被混在一起。
2. 每只基金的日收益用「当前份额 ×（最新净值 − 上一净值）」，今天确认的 11-05 买入份额也被算进 11-05 的跌幅，多算了约 76 元。
3. 收益页用的是「当日总值 − 前一日总值 − 当日转入资金」，能扣掉当天买入，两边口径不一致。

## 修改

### 1. 今日收益与收益页同口径

- `FundReturnService` 新增 `CalculateDailyProfitsForDate`，按收益页的差值口径计算某个净值日各持仓的当日收益。
- `FundService` 为每个持仓取自己的最新净值日，分别计算当日收益；基金汇总只在成员共同的净值日上累加，并按平台、类别、基金逐层标记 `HasDailyProfit` 和 `DailyProfitDate`。
- 前端不再使用全局最新日期，而是从当前分组内已披露的基金里取最新净值日，只累加该日已披露的基金，并显示「按 X 净值 · 仅 Y/Z 只基金披露」。
- 分组筛选后按该分组的净值日重新汇总：例如「纳斯达克100」两只基金都停在 11-05，顶部显示 11-05 的完整合计；全部基金里银华已到 11-06，顶部显示 11-06 的 +401.18，并注明仅 1/8 只基金披露。

### 2. 列表指标改为累计收益率

- 默认指标从「日收益 / 持有收益 / 累计收益」改为 **日收益 / 累计收益率 / 累计收益**。
- 移除「持有收益」和「持有收益率」选项，新增「累计收益率」。
- 累计收益率 =（持有收益 + 已实现收益）÷ 持仓成本，持仓成本为 0 或行情待补时显示 `—` / `行情待补`。
- 指标存储键升到 `lifeup.fund.metrics.v3`，避免旧的 `profit` 配置残留。

### 3. 日收益金额后显示收益率

基金列表的日收益从「金额 + 标签旁的小字」改为：

```text
-6,574.96（-6.29%）
```

未披露该日净值的基金显示 `—`。

### 4. 今日收益旁的更新进度环

- Hero 说明行加入 18px SVG 圆环，显示当前分组内最新净值日的基金披露进度；切换分组后按当前范围重新计算。
- 刷新中：不确定进度环旋转，文案「更新中… · 1/8」。
- 部分披露：圆环按 `已披露/总数` 显示，文案「按 X 净值 · 仅 1/8 只基金披露」。
- 全部披露：满环，文案只保留「按 X 净值」；当天已完整时不显示说明行。
- 上次刷新有基金失败：圆环和文案转为琥珀色「更新失败」。
- 基金页每 15 秒读取一次 `/api/ledger/quotes/status`，页面隐藏时跳过；刷新结束后自动重载基金总览。
- `UpdateRing.vue` 使用 `stroke-dasharray`，带 `role="progressbar"` 和 `aria-valuenow/valuemax`；`prefers-reduced-motion` 时关闭旋转和过渡。

## 遗留

- 11-09 当天多数 QDII 还没有 11-06 净值，所以全部基金顶部暂时只合计银华。等数据源补齐 11-06 后，下一次刷新会自动纳入。
- 累计收益率沿用剩余持仓成本作分母；已实现收益较大时，这个分母不等于累计投入成本。如果需要严格的累计投入口径，需要再补一份历史卖出成本数据。
