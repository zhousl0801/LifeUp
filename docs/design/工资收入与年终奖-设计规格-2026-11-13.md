# 工资收入与年终奖 · 设计规格 V1.0

日期：2026-11-13
状态：口径已确认，待评审后进入实现计划
关联：[资本积累与目标设计规格](资本积累与目标-设计规格-2026-11-12.md)、[自动记账开发记录](../development/2026-10-22-开发记录-自动记账计划与后台任务.md)、[产品设计 V1.1](../product/LifeUp-产品设计文档-V1.1.md)

## 1. 范围

### 1.1 本版纳入

- 「我的 → 个人信息」新增「工资档案」：税前 Base、每月税后工资、公积金月缴存（个人＋单位合计）、年终奖月数、年终奖到手、年终奖发放月、发薪日。
- 工资档案保存时同步三个自动计划：工资到账、公积金缴存、年终奖到账。
- 工资档案作为资本积累预测的默认来源：月收入、公积金月缴存、年终奖。
- 资本假设新增年终奖金额与发放月，并支持「跟随工资档案 / 手动覆盖」。
- 预测按发放月计入年终奖，达成时间、年度表、图表和本月实际同步变化。
- 工资档案进入完整备份，备份版本从 4 升到 5，兼容 1–4。
- 产品文档、接口文档和开发记录同步。

### 1.2 本版不做

- 个税、社保、专项附加扣除的完整计算；只记录用户填写的到手金额。
- 公积金个人与单位拆分；只记录合计。
- 多次调薪历史、按生效日期分段；只保留当前档案。
- 年终奖单独计税估算；到手金额由用户填写。
- 年终奖发放日与发薪日不同；统一使用发薪日，生成后可在账单里修改记录日期。
- 公积金提取对预测分桶的影响；提取仍是资产转移，不计入总资本。
- 多份工资或兼职收入；现有定期收入计划的约束不变。

### 1.3 关键决策

| 事项 | 决策 |
| --- | --- |
| 主数据 | 工资档案是工资、公积金、年终奖金额的唯一入口 |
| 年终奖口径 | 月数 × 税前 Base 作为税前年包参考；预测和入账使用单独填写的到手金额 |
| 公积金 | 只填个人＋单位合计，和现有缴存计划一致 |
| 预测联动 | 默认跟随工资档案；资本假设可切换手动覆盖 |
| 月均积累 | 保持每月实际值（含公积金），年终奖单独展示，不摊平 |
| 年终奖记账 | 新增「年终奖到账」计划类型和「每年」周期，发放月自动记一笔收入 |
| 计划金额 | 管理中的工资、公积金、年终奖计划金额只读，日程仍可调整 |
| 备份版本 | 4 升到 5，新增字段可空，旧备份继续可恢复 |

## 2. 术语与口径

```text
税前年包 = 税前 Base × 12 + 税前 Base × 年终奖月数
税后现金收入 = 每月税后工资 × 12 + 年终奖到手
公积金年入账 = 公积金月缴存（个人＋单位）× 12
月均积累 = 每月税后工资 − 月支出 + 公积金月缴存
年积累 = 月均积累 × 12 + 年终奖到手
```

- 年终奖到手只用于预测和自动入账，不从「月数 × Base」推算；税前年包只做展示。
- 月均积累保持月度口径，不把年终奖摊到 12 个月；年终奖在发放月单独计入。
- 公积金缴存只增加公积金余额，不重复计入现金收入；月均积累只加一次。
- 年终奖随收入年增长一起增长；公积金缴存跟随收入增长，沿用现有口径。
- 预期月净积累不含年终奖；「本月实际」在发放月按含年终奖的预期比较。

## 3. 数据模型

### 3.1 工资档案

工资档案是账本级单例，按现有资本目标的方式存成 JSONB，不新增表：

```text
ledgers.salary_profile jsonb null
```

领域对象：

```csharp
public sealed record SalaryProfile(
    decimal BaseMonthlySalary,   // 税前 Base，月
    decimal NetMonthlySalary,    // 税后到手，月
    decimal ProvidentMonthly,    // 个人＋单位合计，月
    decimal BonusMonths,         // 年终奖月数，0–24
    decimal BonusNetAmount,      // 年终奖到手
    int BonusPayoutMonth,        // 1–12
    int PayDay)                  // 发薪日 1–31
```

校验：

| 字段 | 规则 |
| --- | --- |
| BaseMonthlySalary | 大于 0，不超过 10 亿，最多两位小数 |
| NetMonthlySalary | 大于 0，不超过 10 亿，最多两位小数 |
| ProvidentMonthly | 不小于 0，不超过 10 亿，最多两位小数 |
| BonusMonths | 0 到 24，最多两位小数 |
| BonusNetAmount | 不小于 0，不超过 10 亿，最多两位小数；月数大于 0 时必须大于 0 |
| BonusPayoutMonth | 1 到 12 |
| PayDay | 1 到 31；当月没有该日时按月末执行 |

账本提供 `GetSalaryProfile`、`SetSalaryProfile`、`HasValidSalaryProfile`，与资本目标的 JSON 读写方式一致。

### 3.2 自动计划扩展

新增类型和周期：

```csharp
AutoPlanType.BonusIncome
AutoPlanCycle.Yearly
```

新增列：

```text
auto_plans.month_of_year int null
```

- `MonthOfYear` 只在 `Yearly` 周期使用，取值 1–12；`DayOfMonth` 继续表示每月的哪一天，遇到短月按月末。
- 现有计划类型的周期约束不变：工资、公积金缴存、提取只支持每月；基金定投支持每月、每周、交易日；年终奖只支持每年。
- 年终奖计划的期次键为 `Y{yyyy}`，同年只生成一次。
- 年终奖入账使用「奖金」收入分类：优先按系统标识 `bonus` 查找，找不到再按名称「奖金」查找；分类缺失或已停用时回落到「工资」。

### 3.3 资本目标扩展

`CapitalGoal` 继续存 `ledgers.capital_goal` JSONB，新增可空字段：

```text
AnnualBonus        年终奖到手假设，可空
BonusPayoutMonth   年终奖发放月 1–12，可空
UseSalaryProfile   是否跟随工资档案，默认 false
```

- 老目标反序列化后 `UseSalaryProfile=false`，行为不变。
- 第一次创建工资档案时，如果已存在资本目标，服务端把 `UseSalaryProfile` 置为 true；之后不再自动改动。
- 停用工资档案时置为 false，并把空着的工资、公积金、年终奖字段填上档案值，避免预测数字突变。

## 4. 工资档案与计划同步

### 4.1 保存档案

保存在一个账本锁和一次 `SaveChanges` 内完成：先写档案 JSON，再按类型同步计划。每种类型最多一个计划，沿用现有约束。

| 计划 | 类型 / 周期 | 金额 | 日期 | 不存在时 |
| --- | --- | --- | --- | --- |
| 工资到账 | SalaryIncome / Monthly | 税后月工资 | 发薪日 | 创建 |
| 公积金缴存 | ProvidentDeposit / Monthly | 公积金合计 | 发薪日 | 合计大于 0 时创建 |
| 年终奖到账 | BonusIncome / Yearly | 年终奖到手 | 发放月 + 发薪日 | 月数大于 0 时创建 |

- 新建计划从**严格晚于今天**的下一个发薪日或发放日开始，不补记本月已经过去的日期。
- 已存在的计划只更新金额和日期，保留名称、开始日期、执行时间、暂停状态和历史期次。
- 发薪日变化时，`GenerateFrom` 推到今天之后，避免把过去所有期次一次性补建。
- 公积金合计为 0 时不创建计划；已有计划暂停，不删除。从 0 改回大于 0 时，如果计划是因归零被暂停的，自动恢复。
- 年终奖月数从大于 0 变为 0 时暂停年终奖计划，不删除；从 0 变回大于 0 时，如果计划是因这次归零被暂停的，自动恢复。
- 用户手动暂停的管理计划保持暂停，保存档案不会恢复。

### 4.2 计划编辑

- 工资和公积金计划：金额只读并标注「来自工资档案」；名称、发薪日、执行时间仍可改。
- 年终奖计划：不提供通用编辑入口，只保留暂停 / 恢复；名称和金额来自档案。
- 管理中的计划隐藏删除入口，避免连带删除执行历史；需要解除管理时先停用工资档案。
- 工资档案存在时，收入组不再显示「＋ 新增」；停用档案后恢复。

### 4.3 停用档案

- 删除档案 JSON，保留三个计划，金额恢复可编辑。
- 资本目标按 3.3 处理。
- 停用后已有计划的历史期次和流水不变。

### 4.4 首次建立

- 页面用现有工资计划金额预填税后工资、用公积金计划金额预填公积金合计、用工资计划日期预填发薪日；税前 Base 和年终奖信息由用户填写。
- 保存后，如果金额没改，三个计划的金额和日期保持不变，只多出年终奖计划。

## 5. 资本预测

### 5.1 输入解析

`CapitalDefaultResolver` 的优先级：

| 输入 | 跟随档案且档案存在 | 否则 |
| --- | --- | --- |
| 月收入 | 档案税后月工资，来源 `salary` | 目标手填值 > 最近 6 个完整月均值 > 0 |
| 公积金月缴存 | 档案公积金合计，来源 `salary` | 目标手填值 > 历史均值 > 0 |
| 年终奖到手 | 档案年终奖到手，来源 `salary` | 目标手填值 > 0 |
| 发放月 | 档案发放月，来源 `salary` | 目标手填值 > 1 月 |

- 跟随条件：档案存在，且资本目标不存在或 `UseSalaryProfile=true`。
- `salary` 作为新的来源值加入 `CapitalEffectiveInputs`，页面显示「工资档案」。
- 目标手填值保留在 JSON 里，切回手动时继续可用。

### 5.2 月度推演

对第 `t` 个月：

```text
bonus_t = (month == 发放月) ? 年终奖到手 × 收入增长 : 0
net_t   = 月收入_t − 月支出_t + 公积金月缴存_t + bonus_t
```

- 预测仍从下个月开始，年终奖按自然月判断；跨年时按收入年增长放大。
- Hero 的「月均积累」仍是 `月收入 − 月支出 + 公积金月缴存`，不含年终奖。
- 预计达成年月、投影曲线和年度表按 `net_t` 计算；年度表「净储蓄」含年终奖。
- 图表「每月积累」在发放月显示含年终奖的柱子。
- 投影说明增加一条「年终奖按发放月计入。」；不在说明里写具体金额，避免金额隐藏时泄漏。

### 5.3 本月实际

- 预期净积累在发放月加上年终奖，其他月份不变。
- 发放月显示说明「本月为年终奖发放月，差额可能来自到账时间」。
- 实际对照仍是参考，不参与未来推演。

## 6. 接口

### 6.1 工资档案

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/ledger/salary-profile` | 读取档案；未建立时 `profile=null` |
| PUT | `/api/ledger/salary-profile` | 新建或更新档案并同步计划 |
| POST | `/api/ledger/salary-profile/disable` | 停用档案，保留计划 |

请求和响应：

```json
{
  "requestId": "uuid",
  "baseMonthlySalary": 20000,
  "netMonthlySalary": 12000,
  "providentMonthly": 4800,
  "bonusMonths": 4,
  "bonusNetAmount": 60000,
  "bonusPayoutMonth": 1,
  "payDay": 15
}
```

```json
{
  "profile": {
    "baseMonthlySalary": 20000,
    "netMonthlySalary": 12000,
    "providentMonthly": 4800,
    "bonusMonths": 4,
    "bonusNetAmount": 60000,
    "bonusPayoutMonth": 1,
    "payDay": 15
  }
}
```

- 写操作走 `MutationExecutor`，`requestId` 防重复提交。
- 校验失败返回 400，错误文案与字段对应。
- 停用请求体为 `{ "requestId": "uuid" }`。

### 6.2 计划和资本

- `PlanDto`、`SavePlanRequest` 增加 `monthOfYear`；`PlanType` 增加 `bonusIncome`；`cycle` 增加 `yearly`。
- 通用计划接口允许 `bonusIncome/yearly`，但前端不提供手动新建入口。
- `CapitalGoalSettings`、`UpdateCapitalGoalRequest`、`CapitalEffectiveInputs` 增加 `annualBonus`、`bonusPayoutMonth`、`useSalaryProfile`。
- `CapitalOverviewDto` 增加 `hasSalaryProfile`，供假设表单判断是否显示「跟随 / 手动」。

## 7. 前端

### 7.1 自动计划页

- 自动计划页不再显示工资档案卡片；工资档案统一放在「我的 → 个人信息」。
- 收入组标题改为「工资收入」，汇总显示「工资 ¥X/月 · 年终奖 ¥Y/年」。
- 管理中的计划卡片在计划名称旁显示「工资档案」标记，标记不换行；年终奖计划显示「每年 M 月 D 日」。
- 计划表单：管理中的工资、公积金计划金额只读，并提示到「我的 → 个人信息」修改；年终奖计划在档案管理中不出现编辑入口，停用档案后恢复编辑。
- 工资档案存在时，收入组不显示「＋ 新增」。

### 7.2 我的 → 个人信息

- 「我的」页的「个人信息」分栏增加「工资档案」入口，使用与「头像与昵称」相同的 `list-box / list-row` 样式，显示「查看 ›」。
- 入口放在「头像与昵称」之后；不内联展示金额，点击进入 `/salary` 工资档案详情页。
- 「头像与昵称」保留在同一分栏，主题配色放在「个性化设置」。
- 分栏标题之间统一使用 `--space-6` 上间距，个人信息、个性化设置、数据管理的间隔一致。

### 7.3 工资档案详情页

- 顶部为返回按钮、标题「工资档案」和说明，沿用现有详情页的头部、间距和卡片样式。
- 工资档案卡片默认脱敏，所有金额显示为 `••••`；头部提供「显示金额 / 隐藏金额」和「编辑」。
- 已建立时只展示税后和积累口径，不展示税前 Base、税前年终奖或税前年包：

```text
工资档案                          显示金额  编辑
工资、公积金和年终奖
税后工资 ¥12,000/月      公积金（个人＋单位）¥4,800/月
年终奖 ¥60,000
年度到手现金 ¥204,000    公积金年积累 ¥57,600
```

- 「年度到手现金」= 税后工资 × 12 + 年终奖到手；「公积金年积累」= 公积金月缴存 × 12。
- 年终奖只展示到手额度，金额与第二列左对齐；不展示月数或到账月份，发放月只在自动计划的期次里体现。
- 未建立时显示说明和「建立工资档案」；首次打开用现有工资 / 公积金计划金额和发薪日预填。
- 编辑用底部弹层，字段见 3.1；弹层内显示税前年包、税后现金和公积金年入账，供录入时参考。
- 弹层底部提供「停用工资档案」，二次确认，说明保留现有计划。
- 详情页提供「自动计划」入口，跳转到 `/plans` 查看工资 / 公积金 / 年终奖计划。

### 7.4 目标页

- Hero 不展示公积金 / 年终奖说明，只保留月均积累和组合年化；金额隐藏时打码。
- 顶部「目标」功能栏在「调整假设」左侧增加全局金额显示 / 隐藏眼睛，与首页共用 `amountsMasked`。「小眼睛」只切换显示，不改变假设。
- 资本假设弹层新增「年终奖（到手）」和「发放月」。
- 跟随档案时，月收入、公积金、年终奖、发放月显示为只读并标注「工资档案」，提供「改为手动」。
- 改为手动时，用当前生效值预填字段，避免数字跳变。
- 手动时这些字段可编辑；档案存在时提供「改用工资档案」。
- 预览和保存都带上 `useSalaryProfile`；手动值在跟随期间保留，不丢失。
- `UseSalaryProfile=true` 但档案缺失时，按回退口径计算，并提示「工资档案已停用，请改为手动或重新建立」。
- 新建资本目标时如果档案存在，默认跟随工资档案，字段显示档案值。
- 年度表表尾注明「净储蓄含年终奖」。

## 8. 迁移、备份与兼容

### 8.1 数据库迁移

新增迁移，只做增量：

```sql
ALTER TABLE ledgers ADD COLUMN salary_profile jsonb NULL;
ALTER TABLE auto_plans ADD COLUMN month_of_year integer NULL;
-- 已有账本补「奖金」分类系统标识，供年终奖入账使用
UPDATE entry_categories
SET system_key = 'bonus'
WHERE kind = 'Income' AND name = '奖金' AND system_key IS NULL;
```

- 资本目标在 JSONB 里，不需要改表。
- 新分类默认值：工资 `salary`，奖金从空值改为 `bonus`，其他收入保持 `other-income`。
- 迁移文件纳入源码；应用到真实账本库前先导出完整备份，并单独确认授权。
- 开发库未应用迁移前，`/api/ledger/salary-profile` 会因为缺列报错；其余功能不受影响。

### 8.2 备份

- `BackupDocument.CurrentVersion` 从 4 升到 5，最低支持版本仍为 1。
- `BackupLedger` 增加 `SalaryProfileJson`，`BackupPlan` 增加 `MonthOfYear`。
- 恢复 1–4 版备份：档案为空，计划没有发放月；不影响现有数据。旧备份里的「奖金」分类没有系统标识时，年终奖入账按名称回退，不强制改写备份数据。
- 备份校验增加档案 JSON 的有效性检查。

### 8.3 兼容

- 没有工资档案时，自动计划、资本假设和预测的行为与当前完全一致。
- 已有工资和公积金计划不会被自动暂停或删除，只在保存档案时更新金额和日期。
- 资本目标的老 JSON 反序列化后 `UseSalaryProfile=false`。

## 9. 验收

### 9.1 后端

- 档案校验：边界金额、月数、发放月、发薪日、月数大于 0 时到手为 0。
- 计划同步：首次创建、只改金额、改发薪日不补记、暂停保持、年终奖归零暂停与恢复、停用档案。
- 年度期次：`Y2027` 去重、短月月末、下一个发放日、跨年增长。
- 年终奖入账：生成奖金收入、分类回落、期次重复不重复入账。
- 资本解析：跟随档案、手动覆盖、档案缺失回落、停用后字段补齐。
- 预测：发放月计入、月均积累不变、年度表净储蓄含年终奖、目标达成年份提前、负结余仍正确。
- 接口：GET / PUT / disable、400 校验、重复 requestId、409。
- 备份：v5 导出恢复、v4 恢复、档案无效拒绝。

## 10. 风险与边界

- 年终奖到手依赖用户输入，预测准确度取决于这个数字；页面要明确它不是按税率算出来的。
- 自动入账的年终奖金额是档案里的预计值；实际到手不同时，需要在账单里修改那一笔。
- 发薪日变化会把生成起点推到之后，可能跳过一个尚未执行的本月期次；弹层要写明「只影响未发生的期次」。
- 工资档案与计划的一致性由服务端保存时保证；绕过页面直接改计划金额，会在下次保存档案时被覆盖。
- 迁移是增量且可空，但仍属于对真实账本库的写操作；执行前必须备份并取得授权。
