## 1. 背景与目标

原「资本积累与目标」模块依赖用户手填一个孤立的目标金额（如 100 万），与真实生活开销脱节，难以回答用户最关心的三个问题：

1. **要达到多少被动现金流，才能覆盖我的真实生活开销？**
2. **按我现在的资产、储蓄速度和收益假设，还要积累多久才能自由？**
3. **我现在走到了哪一步？怎么调整支出或配置能最快缩短时间？**

本版将目标模块升级为 **FIRE（财务独立、提前退休）模块**，充分利用 LifeUp 已有的真实账单支出、分类分组、总资产结构与工资档案数据，同时保留「自定义固定金额目标」作为备选模式，确保平滑演进、零数据破坏。

### 1.1 关键决策

| 事项 | 决策 |
| --- | --- |
| 资产口径 | 沿用全部总资产（现金 + 基金 + 股票 + 积存金 + 公积金）；公积金每月可提取租房，视作可流动资产 |
| 提取基准 | 经典安全提取率（SWR），默认 `4.0%`（25 倍年支出），范围 `1.0%–15.0%`，与积累期投资年化独立 |
| 目标模式 | 默认 `fire`（按支出与 SWR 自动计算）；设置弹层顶部保留 `custom`（自定义固定金额）切换入口，互不清空已存字段 |
| 双轨支出 | 同时支持 **Standard FIRE（标准自由）** 与 **Lean FIRE（刚性自由）**；支持按分类排除特定支出、自定义 Lean 分类 |
| 分类分组复用 | Lean FIRE 默认自动纳入账本既有分组「固定」+「必要」下的全部支出分类，开箱即用，支持用户覆盖 |
| 支出假设合一 | 默认合一：积累期月支出取近 12 个完整月全量月均（不因排除某项而虚高储蓄率）；FIRE 支出按分类筛选自动算，且均支持手填覆写 |
| Coast FIRE | 纳入轨道与指标：默认按「25 年后」滑行终点测算（支持用户在假设中设置具体目标年份） |
| 激励与建议 | 纯数据驱动：阶段激励语 + 真实账单分类覆盖匹配 + 内存反算支出/收益/阶段捷径杠杆建议 |
| 导航与命名 | 底部导航「目标」→ **「FIRE」**（火焰双态线性图标）；页内分段「资本积累 / 自动记账」→ **「FIRE / 自动记账」** |
| 数据库与备份 | 扩展既有 `ledgers.capital_goal` JSONB 可选字段；**零数据库迁移**，完全向后兼容 V1–V5 备份 |

### 1.2 本版不做

- 税务、社保断缴测算、退休后分阶段提取策略（如动态提取 VPW）。
- 房贷/负债、房产估值、家庭多成员合并 FIRE。
- 投资标的推荐或具体资产买卖建议（仅提供基于用户自身假设的数学敏感度试算）。
- 在总览首页新增 FIRE 摘要卡（延续底部入口独立承接）。

## 2. 业务口径与计算模型

### 2.1 资产与收入口径（沿用并增强）

```text
FIRE 可计入资产 A0 = 现金(C0) + 投资(I0) + 公积金(P0)
非公积金桶 N0 = C0 + I0
组合年化 r_blend = (I0 × 投资年化 + P0 × 公积金年化) / A0    （A0 = 0 时为 0）
```

- **综合储蓄率**：
  ```text
  年总流入 = 12 × 月收入 + 年终奖 + 12 × 公积金月缴存
  年净积累 = 年总流入 − 12 × 积累期月支出
  综合储蓄率 = 年总流入 > 0 ? round(年净积累 / 年总流入 × 100, 1) : 0
  ```
- **工资档案联动**：完整保留 `useSalaryProfile` 开关，跟随模式下月收入、公积金月缴存与年终奖直接读取工资档案。

### 2.2 真实支出统计窗口与分类筛选

将 `CapitalDefaultResolver` 的历史统计窗口从最多 6 个完整自然月扩展为 **最多 12 个完整自然月**（至少 1 个完整自然月；不计当前未结束月份，也不计账本起始日之前的月份）。

在统计窗口内，按活跃支出记录的分类名称汇总，并除以实际完整月数得到各分类月均支出：

1. **积累期月支出（`monthlyExpense`）**
   - 若用户手填 `monthlyExpense`，使用手填值（`source = "user"`）；
   - 否则使用窗口内**全部支出分类**的月均支出（`source = "history"`）；无完整月历史时为 `0`（`source = "default"`）。
2. **Standard FIRE 月支出（`standardMonthlyExpense`）**
   - 若用户手填 `fireMonthlyExpenseOverride`，使用手填值（`source = "user"`）；
   - 否则若存在完整月历史，取「全部支出分类 − `excludedExpenseCategories`」的月均支出（`source = "history"`）；
   - 否则回退到当前有效积累期月支出（`source = "default"`）。
3. **Lean FIRE 月支出（`leanMonthlyExpense`）**
   - 若用户手填 `leanMonthlyExpenseOverride`，使用手填值（`source = "user"`）；
   - 否则若存在完整月历史：
     - 若 `leanExpenseCategories` 已配置（非 `null`），取该集合内且未被排除的分类月均之和；
     - 若 `leanExpenseCategories` 为 `null`，默认取账本中所属父分组名称为 `固定` 或 `必要` 的所有支出分类（若无分组信息，则回退默认刚性分类集合：`房租、订阅、餐饮、日用、交通、居家、服饰、通讯、医疗`）；
   - 否则若无完整月历史，回退 `round(standardMonthlyExpense × 0.7, 2)`（`source = "default"`）。

> 说明：分类按名称关联账本的 `EntryCategory` 树，返回给前端完整的「分类月均列表 + 所属分组 + 当前归属状态（Lean / 仅 Standard / 已排除）」，方便在设置弹层一键点选。

### 2.3 FIRE 现金流与动态目标计算

设安全提取率 $s = \text{safeWithdrawalRatePercent} / 100$（默认 $0.04$），某模式（Standard 或 Lean）的基础月支出为 $e_0$，基础年支出 $E_0 = 12 \times e_0$，支出年增长率 $g_e = \text{expenseGrowthPercent} / 100$：

```text
当前目标月现金流 = e0
当前目标年现金流 = E0 = 12 × e0
当前 FIRE 目标本金 T0 = E0 / s                    （e0 = 0 时视为未形成有效支出基准）

当前被动月现金流 = round(A0 × s / 12, 2)
当前被动年现金流 = round(A0 × s, 2)
月现金流缺口 = max(0, e0 − 当前被动月现金流)
FIRE 自由度进度 = T0 > 0 ? round(min(100, A0 / T0 × 100), 1) : 0
```

**逐月动态推演判定**（沿用现有逐月复利模型，最多推演 1200 个月 / 100 年）：

对第 $t$ 个月（所属年份偏移 `yearOffset = month.Year - AsOfDate.Year`）：
```text
当月预期年支出 E_t = round(E0 × (1 + g_e)^yearOffset, 2)
当月动态目标本金 T_t = round(E_t / s, 2)
当月被动年现金流 C_t = round(A_t × s, 2)
当月被动月现金流 c_t = round(C_t / 12, 2)
```
- 首个满足 $C_t \ge E_t$（等价于 $A_t \ge T_t$）的月份，即为该模式的 **FIRE 达成年月**（`etaMonth`、`monthsRemaining`）。
- 若起点即满足 $A_0 \times s \ge E_0$，状态为 `reached`。
- 若基础年支出 $E_0 = 0$（例如刚建账且未填支出），状态为 `noTarget`，引导用户记账或手动输入预期月支出。
- 每次 `GET /api/ledger/capital` 与 `POST /api/ledger/capital/preview` 都会同时算出 Standard 与 Lean 两套核心摘要（目标本金、目标月现金流、进度、预计达成年月、剩余月数），并在当前选中的模式上输出完整曲线与年度表。

### 2.4 Coast FIRE（滑行自由）模型

- **目标年份（`coastTargetYear`）**：
  - 用户可在设置中填写目标自然退休/滑行终点年份（范围 `当前年 + 1` 至 `当前年 + 70`）；
  - 未填写时默认 `AsOfDate.Year + 25`（标注 `source = "default"`），开箱可用。
- **滑行阈值与预计达成计算**：
  - 设 $N = \text{coastTargetYear} - \text{AsOfDate.Year}$（$N \ge 1$），组合年化 $r = r_{\text{blend}} / 100$：
  - 若 $r \le 0$ 或 $r \le g_e$（组合收益无法跑赢支出增长）：标记 `achievable = false`，`note = "当前组合年化不高于支出年增长，暂无法仅靠复利滑行"`。
  - 若 $r > g_e$：
    ```text
    终点年 FIRE 目标本金 T_end = (E0 × (1 + g_e)^N) / s
    当前 Coast FIRE 阈值 Coast_0 = round(T_end / (1 + r)^N, 2)
    ```
  - 若 $A_0 \ge \text{Coast}_0$：标记 `reached = true`（已达成 Coast FIRE）。
  - 否则在月度推演循环中，对每个月 $t$（只要 $t < 12 \times N$），计算剩余年数 $N_t = N - t / 12$ 与当月滑行阈值 $\text{Coast}_t = T_{\text{end}} / (1 + r)^{N_t}$，记录首个满足 $A_t \ge \text{Coast}_t$ 的月份作为 `etaMonth` 与 `monthsRemaining`。

### 2.5 轨道里程碑规则（`GlassTrack`）

- **`custom` 模式**：保持既有按自定义目标 10%–90% 自动生成的历史星标逻辑不变。
- **`fire` 模式**：生成语义化里程碑节点（每个节点带 `key`、`label`、`thresholdAmount`、`progressPercent`、`reached`、`date`（已达成取历史首达日期，未达成取预计达成年月）、`description`）：
  1. **应急垫**：`threshold = 1 × E0`（1 年生活费；4% SWR 下约位于 4% 处）
  2. **Coast FIRE**：`threshold = Coast_0`（仅当 `achievable = true` 且 `Coast_0 < T0` 时显示）
  3. **半退休**：`threshold = 0.5 × T0`（被动现金流覆盖 50% 开销）
  4. **Lean FIRE**：仅在当前查看 `standard` 模式且 `0 < leanTarget < standardTarget` 时显示，位置为 `leanTarget / standardTarget × 100%`
  5. **FIRE 终点**：`100%` 终点菱形
- **防重叠展示**：前端渲染标签时若相邻节点间距小于 14%，轨道上保留星标点（均可点击弹出详情气泡），底部文字标签按优先级（`FIRE` > `半退休` > `Lean` > `Coast` > `应急垫`）自动避让隐藏重叠文字。

### 2.6 激励与动态建议引擎（`FireInsightBuilder`）

完全在服务端纯计算生成，随预览/保存实时更新，包含两部分：

1. **阶段状态与激励语（1 条）**

   | 进度区间 | 阶段标签 | 文案要素 |
   | --- | --- | --- |
   | `0% – <10%` | 起步期 | 展示资产可支撑的「应急生活月数（$A_0 / e_0$）」 |
   | `10% – <25%` | 筑基期 | 展示「每天睡后被动收入（$A_0 \times s / 365$）」与复利起步 |
   | `25% – <50%` | 加速期 | 贪心匹配近 12 个月真实支出分类（优先刚性分类，最多 2–3 个），告知「被动月薪已覆盖『X + Y』开销」，并给距半退休时间 |
   | `50% – <80%` | 半自由期 | 恭喜跨过半退休线，展示已覆盖的开销比例与真实分类 |
   | `80% – <100%` | 冲刺期 | 提示距自由仅剩具体月数，注意守住回撤、保持节奏 |
   | `≥ 100%` | 已自由 | 祝贺达成 FIRE，被动现金流已完全覆盖目标开销 |

2. **可执行加速建议（最多 3 条，每条包含 `badge` + `text`）**
   - **支出双倍杠杆**：模拟月支出（积累期与目标基准同步）减少 `delta`（默认 `500` 元；若当前目标月支出 `< 2000` 元则取 `200` 元），内存重跑一次推演，给出「目标本金减少 ¥X 万，自由时间提前 Y 个月」。
   - **阶段捷径**：当前处于 `standard` 模式且尚未达成 Lean FIRE、且 Lean 比 Standard 早至少 1 个月时，给出「先以 Lean FIRE（¥X/月）为阶段目标，预计 YYYY 年 M 月达成，可提前 A 年 B 个月」。
   - **Coast FIRE 捷径**：若尚未达成 Coast FIRE 且预计达成时间早于完全 FIRE 至少 6 个月，提示「预计 YYYY 年 M 月达成 Coast FIRE，届时停止额外储蓄也能在目标年份自然自由」。
   - **收益 / 配置敏感度**：
     - 若投资年化 `= 0%` 或无投资资产：试算按 `4%` 稳健组合年化可提前的时间，温和提示试算配置效果；
     - 否则试算投资年化 `+1%` 可提前的月数。
   - **高储蓄率正向反馈**：综合储蓄率 `≥ 50%` 时补充正向肯定。

## 3. 数据模型与接口设计

### 3.1 领域模型扩展（`CapitalGoal`）

在 [CapitalGoal.cs](file:///Users/zhousl/个人/个人项目/lifeUp/api/src/LifeUp.Domain/Ledgers/CapitalGoal.cs) 末尾追加带默认值的可选参数（旧 JSON 反序列化自动回落默认值，无需数据库迁移）：

```csharp
public sealed record CapitalGoal(
    decimal? TargetAmount,
    decimal? MonthlyIncome,
    decimal? MonthlyExpense,
    decimal? MonthlyProvidentDeposit,
    decimal? IncomeGrowthPercent,

    decimal? LeanMonthlyExpenseOverride = null,
```

校验规则补充：

- `SafeWithdrawalRatePercent` 可空，非空时必须在 `[1, 15]` 且最多两位小数。
- `FireMonthlyExpenseOverride` / `LeanMonthlyExpenseOverride` 可空，非空时必须 `>= 0`、`<= MaximumAmount` 且最多两位小数。
- `CoastTargetYear` 可空，非空时必须在 `[2025, 2200]`。
- 分类名称列表自动去重、去空白；长度上限 100 项。
