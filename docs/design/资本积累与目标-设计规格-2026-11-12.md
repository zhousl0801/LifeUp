## 1. 范围

### 1.1 本版纳入

- 设定一个资本目标，按总资产口径计算进度。
- 一组月度假设：月收入、月支出、公积金月缴存、收入年增长、支出年增长、投资年化、公积金年化。
- 按月推演资本、投资收益和年度积累，给出预计达成年月。
- 目标页的玻璃轨道：已完成段、未来段、当前光标、年月标签、历史里程碑、终点菱形、动态进度。
- 「本月实际」与假设的对照。
- 底部导航新增「目标」，原「计划」并入目标页；页内分段「资本积累 / 自动计划」。
- 目标与假设的持久化、备份恢复、产品文档和接口文档同步。
- 由系统按目标自动生成里程碑，不新增手动记录入口。

### 1.2 本版不做

- 手动资本记录、备注或记录列表。星标是自动里程碑，不是手动账本。
- 多个目标并列跟踪。
- 目标日期反推、收入/支出按月单独设定、情景对比（保守/基准/乐观）。
- 通胀调整、实际购买力、税务。
- 负债、房产、信用卡、家庭共享。
- 投资建议或买卖建议。
- 在首页增加资本积累摘要入口。

### 1.3 关键决策

| 事项 | 决策 |
| --- | --- |
| 目标口径 | 总资产达到目标金额；现有资产计入进度 |
| 收益模型 | 现金 0%；基金/股票/积存金合并为投资桶，按一个投资年化；公积金单独 1.5%（可改） |
| 时间粒度 | 固定月度假设，收入/支出各带一个可选的年增长率，默认 0% |
| 投影起点 | 下个月；本月只做实际对照 |
| 新增资金 | 净积累进入非公积金桶，按当前现金/投资比例分配；公积金缴存单独进入公积金桶 |
| 负结余 | 先扣非公积金资本，再扣公积金；总资本不低于 0；耗尽后停止推演 |
| 目标页位置 | 底部导航「目标」替换「计划」，页内分段「资本积累 / 自动计划」 |
| 视觉方向 | A+C 混合：A 的页面骨架 + C 的净积累/收益分层；轨道为玻璃槽 |
| 星标 | 按目标 10% 自动生成的里程碑，日期取历史资产首次达到阈值的日期 |
| 光标月份 | 当前业务月份；不随单次记录回填过去月份 |
| 备份版本 | 从 3 升到 4，兼容 1–3 |

## 2. 术语与口径

沿用产品设计的资产口径：

```text
总资产 = 现金 + 基金 + 公积金 + 积存金 + 股票
已记录资产 = 已录入或已标记不持有的资产合计
资本积累 = 总资产变化 = 净积累 + 投资收益
净积累 = 生活结余 + 公积金缴存 = (日常收入 − 消费支出) + 公积金缴存
投资收益 = 基金/股票/积存金市值变化，含确认费用和价差
```

- **资产转移不计入积累**：基金定投、公积金提取、现金买入基金/股票/积存金、赎回到账，只是资产换口袋。
- **预期月净积累**：`月收入 − 月支出 + 公积金月缴存`。Hero 的「月均积累」显示这个值，不含投资收益。
- **组合年化**：按当前资产结构加权的年化收益率，含投资桶和公积金桶，现金按 0%。它是折算值，不是新的输入。
- **名义金额**：预测不扣通胀；页面不展示通胀说明，避免增加噪音，但设计文档和设置说明保留这一约定。
- **四类资产未覆盖完整**：页面使用「已记录资产」而非「总资产」，并提示可能偏低。

## 3. 计算模型

### 3.1 起点与分桶

设：

```text
C0 = 现金
I0 = 基金 + 股票 + 积存金（含待确认、待到账金额，与总资产口径一致）
P0 = 公积金
A0 = C0 + I0 + P0
```

- `A0` 是预测起点。覆盖完整时用总资产；否则用已记录资产并标记 `coverageComplete=false`。
- 非公积金桶 `N0 = C0 + I0`；公积金桶 `P0`。
- 如果 `I0 = 0`，投资年化对非公积金桶不生效，页面提示「当前没有投资资产，投资年化暂不生效」。
- 如果 `A0 = 0`，预测仍可运行，但从 0 开始；页面提示先录入资产。

### 3.2 月度推演

预测从**下个月**开始，当前月不计入未来月份，避免重复计算本月已发生的部分。

对第 `t` 个月：

```text
s_t = 月收入_t − 月支出_t                    // 净储蓄
d_t = 公积金月缴存_t                         // 单独进入公积金桶

r_n = 投资年化 × I0 / (C0 + I0)              // 非公积金桶加权收益率
r_p = 公积金年化

m_n = (1 + r_n)^(1/12) − 1
m_p = (1 + r_p)^(1/12) − 1

N_{t+1} = N_t × (1 + m_n) + s_t
P_{t+1} = P_t × (1 + m_p) + d_t
A_t = N_t + P_t

r_blend = (I0 × 投资年化 + P0 × 公积金年化) / A0
```

`r_blend` 是 Hero 的「组合年化」，按当前资产结构折算；它不是新增输入。

- **月末投入、按月复利**：当月新增净积累不计当月收益。
- **年增长在每年 1 月 1 日生效**：收入、支出各按自己的增长率；公积金缴存跟随收入增长。当前年度使用基础值。默认 0%，不填即直线推演。
- **新资金分配**：`s_t` 进入非公积金桶，并按当前 `C0:I0` 比例分配。页面注明「按当前资产结构推演」。
- **公积金缴存**：`d_t` 只进入公积金桶，不经过非公积金桶。

### 3.3 负结余与耗尽

不模拟借贷，总资本不会低于 0：

1. `s_t < 0` 时先扣减 N。
2. N 不足时从 P 扣减。
3. 两者都耗尽后，总资本记为 0，对外状态为 `depleted`，给出耗尽年月并停止推演。

页面显示「按当前假设无法维持支出」，不画负资产曲线。

### 3.4 达成时间与状态

从下个月起逐月迭代，最多 1200 个月（100 年），在每个月末检查 `A_t ≥ 目标金额`：

| 状态 | 条件 | 页面 |
| --- | --- | --- |
| `reached` | 起点已达成或迭代中达成 | 显示「已达成」；已达成时不再给预计年月 |
| `onTrack` | 100 年内达成 | 显示预计年月 |
| `beyondHorizon` | 100 年仍未达成但资本仍在增长 | 显示「100 年内无法达成」 |
| `unreachable` | 净积累为负、收益不足以抵消，资本不再增长但未耗尽 | 显示「按当前假设无法达成」 |
| `depleted` | 负结余持续，资本被扣减到 0 | 显示「资金耗尽」+ 耗尽年月 |
| `noTarget` | 未设目标 | 不显示达成时间，仍给 10 年推演 |

- 目标已达成时，进度按 100% 显示，光标靠右并做边界对齐。
- 迭代法而不是闭式公式：零收益、负结余、目标已达成、增长生效等边界更稳，同时生成曲线和年度表。

### 3.5 舍入

- 月利率保留 10 位小数；内部金额用 `decimal`，不累积二进制浮点误差。
- 展示金额两位小数；年度表分项四舍五入后，合计可能与年末差额差 0.01，表尾注明。
- 进度百分比保留 1 位小数；预计年月精确到月。
- 金额上限沿用 `LedgerEntry.MaximumAmount = 1,000,000,000`。

### 3.6 默认值

未保存的输入由服务端解析并返回 `source`，页面标明来源：

| 输入 | 默认规则 | 无历史时 |
| --- | --- | --- |
| 月收入 | 最近最多 6 个完整自然月的收支均值 | 0，标「暂无历史」 |
| 月支出 | 同上 | 0 |
| 公积金月缴存 | 同窗口内实际公积金缴存均值 | 0 |
| 收入年增长 | 0% | 0% |
| 支出年增长 | 0% | 0% |
| 投资年化 | 0%，不替用户编收益 | 0% |
| 公积金年化 | 1.5% | 1.5% |

- 「完整自然月」：该月整月落在账本起始日之后，且已经结束；当前月不计。
- 最多取 6 个月，至少 1 个；不足 1 个完整月时不猜均值。
- `source` 取值：`user`（用户保存）、`history`（历史均值）、`default`（默认值）。

### 3.7 本月实际

复用 `MonthChangeService` 的月度变化口径：

```text
实际积累 = ComparableChange
实际净积累 = NetDeposit
实际投资变动 = MarketValueChange
按假设应净积累 = 预期月净积累（含公积金缴存）
差额 = 实际积累 − 按假设应净积累
```

- `ComparableChange` 不可比时显示「—」，不记 0，并注明「本月行情或资产依据不足」。
- 实际积累包含投资市值变动；差额主要来自市值变动和实际收支与假设的偏差。
- 这是「实际对照」，不是预测的一部分，不参与未来推演。

### 3.8 里程碑

星标是自动生成的资本里程碑，不是手动记录。

- 步长 = 目标金额 × 10%，取 `k = 1..9`，即 10% 到 90%；100% 由终点菱形表示。
- 对每个阈值，从历史资产序列中找**首次** `总资产 ≥ 阈值` 的日期；找不到则跳过该星并加说明。
- 星星位置 = 阈值 ÷ 目标金额；标题 = 「资本突破 X 万」（X 按阈值格式化；小于 1 万时用元）。
- 星标点击显示日期和标题；金额隐藏时标题中的数字打码，日期保留。
- 目标金额改变时，阈值和星标重算；这是派生数据，不持久化。
- 历史资产序列复用资产趋势的逐日估值（只读）。账本历史不足时，星标可能缺失或集中在起始日；页面不编造日期。
- 星标只覆盖已经达到的阈值；未达到的未来阈值不显示。
- 目标已达成时，10%–90% 的星标保留，终点菱形填充薄荷绿并显示「已达成」。

### 3.9 年度刻度

轨道下方的年份不是等距时间轴，而是**预测中该年末资本所在的位置**：

- 横轴是资本进度 `0 → 目标金额`，不是日历时间。
- 候选年份：当前年之后的预测年份，不含当前年；最多选 2 个均匀分布的偶数年，再加目标年。
- 位置 = 该年末预测资本 ÷ 目标金额；目标年在 100%。
- 跳过与当前光标或相邻刻度距离小于 8% 的标签，避免重叠。
- 目标在 2 年内时只显示目标年。
- 当前年由光标上方的年月标签承担，轨道下方不重复显示。
- 终点菱形在 100%，与 2033 这类目标年标签对齐。

示例：当前 2026 年、目标 2033 年时，轨道下方显示 2028、2030、2033；位置由预测年末资本决定，不平均分配。

## 4. 数据模型与存储

### 4.1 领域对象

新增 `LifeUp.Domain/Ledgers/CapitalGoal.cs`：

```csharp
public sealed record CapitalGoal(
    decimal? TargetAmount,
    decimal? MonthlyIncome,
    decimal? MonthlyExpense,
    decimal? MonthlyProvidentDeposit,
    decimal? IncomeGrowthPercent,
    decimal? ExpenseGrowthPercent,
    decimal? InvestmentAnnualReturnPercent,
    decimal? ProvidentAnnualReturnPercent);
```

`Ledger` 增加：

```csharp
public string? CapitalGoalJson { get; private set; }
public CapitalGoal? GetCapitalGoal();
public bool SetCapitalGoal(CapitalGoal? goal, DateTimeOffset now);
public bool HasValidCapitalGoal();
```

- `GetCapitalGoal` 读取并反序列化；JSON 无效时抛出 `JsonException`。
- `SetCapitalGoal(null)` 清空目标与假设；写入时 `Touch(now)`，参与并发版本。
- `HasValidCapitalGoal` 供备份恢复校验。

### 4.2 校验

| 字段 | 规则 |
| --- | --- |
| `targetAmount` | `null` 或 `0 < x ≤ 10 亿`，最多两位小数 |
| `monthlyIncome` / `monthlyExpense` / `monthlyProvidentDeposit` | `null` 或 `0 ≤ x ≤ 10 亿`，最多两位小数 |
| 两个增长率 / 两个年化 | `null` 或 `-100 < x ≤ 100`，最多两位小数 |

- 百分比统一存百分数（`4.5` 表示 4.5%），字段名带 `Percent` 后缀。
- `targetAmount = null` 表示未设目标；其他字段 `null` 表示使用默认值，`0` 表示用户明确设为 0。

### 4.3 存储

- 在 `ledgers` 增加 `capital_goal` jsonb 字段，沿用 `monthly_budgets` 的做法。
- `LedgerConfiguration` 映射为 `jsonb`，可空。
- 迁移：`AddLedgerCapitalGoal`，只增加一列。
- 序列化使用 camelCase，与 API 字段一致：

```json
{
  "targetAmount": 1000000,
  "monthlyIncome": 12000,
  "monthlyExpense": 7200,
  "monthlyProvidentDeposit": 2000,
  "incomeGrowthPercent": 3,
  "expenseGrowthPercent": 2,
  "investmentAnnualReturnPercent": 5.0,
  "providentAnnualReturnPercent": 1.5
}
```

### 4.4 不新增表

里程碑、年份刻度、投影都从现有账本、资产和趋势数据派生，不新建表。这样：
- 备份不需要包含投影结果，只包含目标和假设。
- 目标改变后不会留下过期的星标或预测。
- 未来若要支持手动记录，再单独设计记录表，不在本版混入。

## 5. API

### 5.1 路由

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/ledger/capital` | 读取设置、生效假设、当前分桶、预测、里程碑、本月实际 |
| PUT | `/api/ledger/capital` | 保存目标与假设，返回重新计算后的完整结果 |
| POST | `/api/ledger/capital/preview` | 用草稿假设试算，不落库 |

- 账本未初始化：404。
- 校验失败：400，`ProblemDetails` 带字段错误。
- 并发冲突：409，提示「账本刚有新变化，请重试」。
- 三个接口都只读账本或写 `capital_goal`，不产生资产流水。

- 金额隐藏由前端处理，接口返回真实值。

```json
}
```

- 全部字段可空；`targetAmount: null` 清空目标。
- `PUT` 与 `preview` 使用同一套校验和计算。
- `preview` 不写入 `capital_goal`，不触发 `Version` 变化。
- `PUT` 返回 5.2 的完整结构；前端不再额外请求。

### 5.4 并发

- `PUT` 使用 `GetForUpdateAsync`；`SetCapitalGoal` 触发 `Touch`，`Version` 作为并发标记。
- 捕获 `ConcurrencyConflictException`，返回 409；前端保留草稿并提示重试。
- `preview` 使用只读快照，不参与并发。

### 6.3 玻璃轨道

轨道是 Hero 内唯一的高光组件，结构从下到上：

```text
玻璃槽（slot）
  ├─ 未来段：半透明淡紫，上沿反光，下沿内阴影
  ├─ 已完成段：青绿 → 冰蓝渐变，内部发光
  ├─ 里程碑星标：四角星
  ├─ 当前光标：白色短竖条
  ├─ 年月标签：光标上方的深紫胶囊
  └─ 终点菱形：空心菱形
年份文字：轨道下方
```

尺寸与样式：

| 部件 | 规格 |
| --- | --- |
| 轨道高度 | 16px，圆角 999px |
| 轨道宽度 | Hero 内容宽度 |
| 未来段 | `linear-gradient(180deg, rgba(255,255,255,.20), rgba(180,170,255,.10))` |
| 上沿反光 | 轨道内 1px 白色半透明高光 |
| 下沿内阴影 | `inset 0 -2px 3px rgba(20,14,50,.32)` |
| 已完成段 | `linear-gradient(90deg, #6FE3B4 0%, #8FE8D6 45%, #C8F0FF 100%)` |
| 已完成段光晕 | `0 0 18px rgba(126,231,210,.55)` |
| 光标 | 4×28px 白色圆角竖条，顶部高于轨道 10px 左右 |
| 光标光晕 | `0 0 12px rgba(255,255,255,.85)` |
| 年月标签 | 深紫胶囊 `rgba(42,34,112,.92)`，白字 12px/600，圆角 10px |
| 星标 | 白色四角星，14px，带柔光 |
| 终点菱形 | 12px 空心菱形，1.5px 白描边，圆角 2px |
| 年份文字 | 11px，浅紫白，保持清晰、不加发光 |

位置与边界：

- `--progress = min(max(当前总资产 ÷ 目标, 0), 1) × 100%`。
- 已完成段宽度 = `--progress`；光标和标签的 `left = --progress`。
- 元标签边界：进度 < 15% 时左对齐，> 85% 时右对齐，其余居中，避免溢出 Hero。
- 目标未设定：轨道只显示玻璃槽，中央提示「设定目标后显示达成进度」；不显示光标、星标、年份和菱形。
- 已达成：进度 100%，已完成段覆盖整条槽，菱形填充薄荷绿，标签显示「已达成」并做右对齐。
- 金额为 0：进度 0，光标在起点，标签显示当前月份，无星标。
- 覆盖不完整：Hero 标签使用「已记录资产」，轨道下方或 Hero 底部提示「部分资产未录入，结果可能偏低」。

动效：

| 场景 | 行为 |
| --- | --- |
| 首次加载 | 已完成段从 0 长到当前进度，光标和标签跟随，900ms |
| 数据刷新、资本上升 | 已完成段和光标同步延伸 800ms；冰蓝流光从旧位置沿槽追到新位置；跨过新阈值时星标弹出；抵达后光标提亮 380ms，年月标签更新 |
| 数据刷新、资本下降 | 正常过渡到新位置，不播放流光，不弹星标 |
| 星标首次出现 | 缩放淡入 320ms |
| 系统减少动态效果 | 全部动效关闭，直接显示最终状态 |

- 首次加载不播放流光；流光只用于资产数据上升时的「旧位置 → 新位置」更新。
- 旧位置只保存在组件内存；页面刷新按首次加载从 0 开始，避免跨会话误判。
- 标签的文本在流光抵达后更新为当前业务月份；更新前保持旧月份。
- 目标或假设变化只做 600ms 普通过渡，不播放流光、不弹星标；避免用户调低目标时出现虚假的「达成」庆祝。

交互：

- 星标可点击，弹出日期和标题；点击空白关闭。
- 视觉星标 14px；点击热区 32×32px。10% 步长的相邻星标仅约 35px 间距，热区扩大到 44px 会互相重叠，因此这里按密集标记处理，主操作仍保持 44px。
- 轨道容器使用 `role="group"` 和 `aria-label`（当前资本、目标、进度、预计年月）；填充、光标、菱形等装饰层 `aria-hidden`。
- 星标是按钮，`aria-label` 包含日期和标题；金额隐藏时不把金额写进 `aria-label`。
- 光标和标签不单独成为操作目标。

### 6.7 假设表单

底部抽屉，沿用现有 BottomSheet：

**表单顺序与分组**

1. 目标金额（整行）。
2. 月收入 / 月支出（同一行）。
3. 公积金月缴存 / 公积金年化（同一行）。
4. 收入年增长 / 支出年增长（同一行）。
5. 投资年化（整行，带 20 年历史年化快捷项）。

同类字段放在一起：公积金两个字段同组，两个增长率同组；投资年化不与公积金混排。

**目标金额**

- 输入单位固定为**万元**，默认值示例「100」表示 100 万。
- 允许最多 4 位小数（1 元 = 0.0001 万）；提交时转换为元，仍受 10 亿元上限和两位小数校验。
- 留空表示清除目标；输入下方提示「例如 100 表示 100 万」。

**快速应用**

- 月收入：读取启用中的工资 / 定期收入计划，取金额合计；显示「用计划收入 ¥…」按钮。
- 月支出：读取当前月预算；没有预算时回退到上一个完整月的实际支出；显示「用账单预设 ¥…」按钮。
- 公积金月缴存：读取启用中的公积金缴存计划，取金额合计；显示「用缴存设置 ¥…」按钮。
- 点击按钮只填入对应字段，仍触发校验和 300ms 实时预览，不直接保存。
- 没有可用来源时不显示按钮，不显示 0 作为建议。

**投资年化**

- 允许手动填写。
- 提供两个固定历史参考快捷项：「纳指100 20年 ≈13%」和「标普500 20年 ≈10%」。
- 快捷项只写入年化字段，可再手动修改；下方注明「历史年化参考，不代表未来收益」。
- 这两个值是历史参考常量，不接实时指数行情，也不作为投资建议。

**其他**

- 派生行：月净积累、组合年化。
- 留空 = 使用默认值；表单提示「目标按万元填写；留空的假设按最近 6 个月自动估算」。
- 编辑时调用 `POST /preview`，防抖 300ms，页面实时预览；不改变已保存数据。
- 底部「保存并重新计算」；保存失败保留草稿并提示重试。
- 未保存离开时拦截；「恢复假设默认」清空收入、支出、公积金、增长和年化字段，保留目标金额，并触发预览。
- 校验错误显示在对应字段下方，不只弹 toast。
- 金额（非目标）最多两位小数；百分比最多两位小数，范围 -100 到 100。

## 11. 评审关注点

以下三点是本版按当前讨论确定、但值得在评审时再确认的：

1. **星标是自动里程碑，不是手动记录。** 如果希望用户手动添加带标题的记录，需要新增记录表和记录管理入口，范围会扩大。
2. **年份刻度按预测资本位置摆放，不是等距时间轴。** 这样横轴与光标、进度保持同一口径；代价是年份间距不均匀。
3. **「月均积累」不含投资收益，只表示每月可投入的净积累。** 投资收益通过「组合年化」和年度表体现。
4. **光标标签是当前业务月份，不是最近一条账本记录的日期。** 补录历史记录时不会让光标倒退；如果希望标签显示某条记录的日期，需要引入手动记录模型。
